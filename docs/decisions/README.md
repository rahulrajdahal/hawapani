# Architectural Decision Records (ADRs)

## Purpose

This directory records significant architectural decisions that shape the hawapani codebase.

## When to Create an ADR

Create an ADR when a decision:

- Modifies fundamental application architecture or routing models.
- Introduces or removes a significant dependency or library.
- Changes data fetching, caching, or retry strategies.
- Introduces major security or accessibility mechanisms.
- Alters testing philosophies or CI deployment workflows.

## Standard ADR Format

```markdown
# ADR-[NNNN]: [Decision Title]

## Status

[Proposed | Accepted | Deprecated | Superseded]

## Context

What problem are we solving? What constraints exist?

## Decision

What is the change and how is it implemented?

## Alternatives Considered

What alternatives were evaluated and why were they rejected?

## Consequences

What are the positive and negative implications of this decision?

## Date

YYYY-MM-DD
```
